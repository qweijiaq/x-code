# X-Code 1.0.2

This release gives skills their own dependency environment and fixes the
over-eager "shell failed" reporting.

**Download:** [X-Code 1.0.2 release assets](https://github.com/qweijiaq/x-code/releases/latest)
(`X-Code-1.0.2-arm64.dmg`, `SHA256SUMS`, `RELEASE.json`).

## Skill runtime

Skills that ship a `requirements.txt`, `pyproject.toml` or `package.json` now
get an isolated environment under `~/.x-code/skill-runtime/<skill>`:

- **Install dependencies** from Settings → Skills creates a Python venv or
  Node `node_modules` in the runtime directory, never in the project.
- The activation payload tells the model the exact interpreter/module paths
  and to keep dependency work out of the workspace.
- **Clear runtime** removes the isolated environment.
- **Clean legacy runtime** removes `runtime/`, `.runtime/`, `venv/` or
  `.venv/` folders that older third-party installers left inside the skill
  directory. `SKILL.md` and scripts are never removed.
- Project-scoped skills still work; their dependencies go to the same
  user-level runtime directory.
- Python/Node installers run from the trusted app process, so they can use the
  network and `~/.x-code` even when the agent's shell sandbox is enabled.

Skills that download models or other assets **at run time** still execute
through the agent shell. If the shell sandbox denies network, enable
“Allow network” in Settings → Tools for those skills.

## Shell results

A command that exits non-zero (`grep` with no match, `command -v` missing, a
failing test) is now a normal tool result with its exit code and output, not a
red tool failure. Only spawn failures, timeouts, signal termination and
sandbox/permission denials are reported as tool errors.

This was the main cause of “shell often fails”: the commands themselves were
returning 1/6/127, not being blocked by permissions. Real sandbox denials
(`Operation not permitted` for network or writes outside the workspace) still
appear as failures; the macOS profile now also allows writes inside the
app-managed `~/.x-code/skill-runtime`.

## Install

1. Download `X-Code-1.0.2-arm64.dmg` and verify it:

   ```bash
   shasum -a 256 -c SHA256SUMS
   ```

2. Drag **X-Code** to Applications.
3. The community build is ad-hoc signed, not notarized. Approve the first
   launch in **System Settings → Privacy & Security → Open Anyway**; if macOS
   reports the app is damaged, clear the quarantine flag:

   ```bash
   xattr -dr com.apple.quarantine /Applications/X-Code.app
   ```

Full steps: [unsigned install guide](../desktop-install-unsigned.en.md).

Existing 1.0.1 users can open **Settings → Desktop updates**, check for 1.0.2,
download the dmg and install manually.
