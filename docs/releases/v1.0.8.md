# X-Code 1.0.8

Clearer progress while a turn runs, calmer tool cards, and sandbox failures that
say what happened.

## Turn status

- A strip above the composer now shows what the current turn is doing — waiting
  for the model, generating a reply, running a tool, waiting for approval, or
  retrying — with an elapsed clock.
- Running tool cards show their own elapsed time. When a stage has been quiet for
  a while after progress, the strip adds a "no new output" hint, so a slow step
  no longer looks like a frozen reply.
- Background-task bars only appear when background work is actually running; the
  duplicate Markdown toolbar in the composer is gone.

## Tool cards and diffs

- A code diff now opens as a four-line preview with its `+ / −` counts. Expand it
  in place, or use "Show N more lines"; an expanded diff keeps a fixed height and
  scrolls internally.
- Sub-agent logs start collapsed and keep their status and duration in the
  header.

## Sandbox guidance

- Sandbox failures are classified instead of showing npm's generic advice:
  - GUI apps such as Electron and Chromium cannot start inside the X-Code shell
    sandbox (nested sandbox rejected by the system) and cannot write `~/Library`.
  - npm and pip need their user cache (for example `~/.npm`), which the sandbox
    only allows for the workspace and temp directories.
- Every hint with a shell command offers **Run in terminal**: it opens the
  right-hand terminal in the current workspace and runs the same command there.
  The terminal is not sandboxed, and the command runs only once.

## Default workspace

- Launching without a project folder now opens `~/.x-code/workspace`, with a
  sidebar/onboarding entry for quick questions and `xc --scratch` on the CLI.

## Install

The community build is unsigned. See
[the unsigned install guide](../desktop-install-unsigned.en.md) if macOS blocks
the first launch.
