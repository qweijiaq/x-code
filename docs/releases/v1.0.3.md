# X-Code 1.0.3

A focused fix for the in-app update downloader.

**Download:** [X-Code 1.0.3 release assets](https://github.com/qweijiaq/x-code/releases/latest)
(`X-Code-1.0.3-arm64.dmg`, `SHA256SUMS`, `RELEASE.json`).

## Fixes

- **Visible download progress.** The update panel now shows downloaded bytes,
  total size, speed and a percentage/progress bar instead of an indefinite
  “Downloading…” label.
- **Slow downloads no longer fail at 10 minutes.** The old fixed total timeout
  is replaced with a 60-second _no-data_ timeout, so a slow but steady 245 MB
  download can finish.
- **You choose where the installer goes.** Updates download to the system
  Downloads folder by default; **Choose location** opens a native save dialog.
  The panel shows the final path and offers **Show in Finder**.
- **Cancel an in-flight download.** A cancel button aborts the request and
  removes the partial file.
- **Update checks work behind a system proxy.** The check/download path now
  uses Chromium's network stack (`net.fetch`) instead of Node's `fetch`, which
  ignored the macOS proxy and aborted with “The operation was aborted due to
  timeout”. The feed timeout is also raised from 8s to 20s.
- **Background task timers now count up.** Elapsed time was computed with
  `performance.now()` against a `Date.now()` start timestamp, which clamped to
  `00:00`. The panel now shows real elapsed time; Python tasks also run with
  `PYTHONUNBUFFERED=1`, so progress they print appears in the panel instead of
  waiting for the process to exit.
- **Stop waiting for a background task.** When the current reply is blocked
  waiting on a background shell, the composer shows a banner with **Stop
  waiting** (and **Stop waiting and run queued** when prompts are queued). It
  aborts only the current reply; the background task keeps running.
- Partial files are removed when a download fails or the SHA-256 check fails.

## Workspace check

When a prompt references an absolute path outside the active workspace
(`/Users/...`, `~/...`, `/Volumes/...` or a Windows drive), X-Code now shows a
confirmation instead of silently acting on another project:

- it lists the current workspace and the external path(s);
- **Run in this workspace anyway** continues;
- **Cancel** keeps the prompt and attachments in the composer so you can switch
  projects from the sidebar;
- **Don’t warn again this session** suppresses the check until restart.

Paths inside the workspace, URLs and system paths (`/usr`, `/tmp`, …) are
ignored. The check is a client-side guard; the agent’s actual permissions and
sandbox rules are unchanged.

## Install

1. Download `X-Code-1.0.3-arm64.dmg` and verify it:

   ```bash
   shasum -a 256 -c SHA256SUMS
   ```

2. Drag **X-Code** to Applications.
3. The community build is ad-hoc signed, not notarized. Approve the first
   launch in **System Settings → Privacy & Security → Open Anyway**; if macOS
   reports the app is damaged, clear the quarantine flag:

   ```bash
   xattr -dr com.apple.quarantine /Applications/X-Code.app
   ```

Full steps: [unsigned install guide](../desktop-install-unsigned.en.md).
